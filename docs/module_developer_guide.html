Module Developer Guide

EnumScan uses a modular design where individual security scanning features are implemented as self-contained Go packages under internal/modules/.

Module Interface Contract

Every module must implement the standard Module interface defined in internal/models/models.go:

type Module interface {
    Name() string
    SubscribedEvents() []string
    Execute(ctx context.Context, evt Event, bus EventBus) error
}

Step-by-Step Implementation Guide

  1. Create Module Package: Create a new file in internal/modules/ (e.g., my_module.go).
  2. Implement the Interface:
package modules

import (
    "context"
    "fmt"

    "enumscan/internal/models"
)

type MyCustomModule struct{}

func NewMyCustomModule() *MyCustomModule {
    return &MyCustomModule{}
}

func (m *MyCustomModule) Name() string {
    return "my_custom_module"
}

func (m *MyCustomModule) SubscribedEvents() []string {
    return []string{"host.discovered", "port.open"}
}

func (m *MyCustomModule) Execute(ctx context.Context, evt models.Event, bus models.EventBus) error {
    if evt.Target == "" {
        return nil
    }

    result := fmt.Sprintf("analyzed %s", evt.Target)

    bus.Publish(models.Event{
        ScanID: evt.ScanID,
        Type:   "asset.discovered",
        Target: result,
        Module: m.Name(),
    })

    return nil
}
  1. Register Module in Engine: Register the new module instance inside internal/engine/engine.go during engine initialization.

Developer Best Practices

  1. Context Cancellation: Always honor ctx.Done() within long-running network connections to support graceful scan cancellation.
  2. Error Isolation: Failures within a single module execution should return an error to log telemetry without crashing the scan run.
  3. No Intrusive Exploitation: Modules must perform passive enumeration or standard protocol handshake analysis only.
