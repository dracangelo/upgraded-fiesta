Plugin SDK Documentation

EnumScan provides a flexible Plugin SDK enabling custom enumeration logic via Lua scripts and external gRPC plugins. Plugins run in sandboxed environments to maintain system safety.

1. Lua Plugin Development

Lua plugins reside in the plugins/ directory. Each script defines metadata and an execution callback.

name = "custom_banner_check"
version = "1.0.0"
subscribed_events = { "port.open" }

function execute(event)
    print("[Lua Plugin] Processing event on target: " .. event.Target)
    
    if string.find(event.Target, "80") then
        emit_asset(event.ScanID, "web_service", event.Target, "Lua banner match")
    end
end

2. gRPC External Plugins

External binary plugins communicate with EnumScan over gRPC sockets using proto definitions.

syntax = "proto3";
package plugin;

service PluginService {
    rpc Execute (PluginRequest) returns (PluginResponse);
}

message PluginRequest {
    string scan_id = 1;
    string event_type = 2;
    string target = 3;
}

message PluginResponse {
    bool success = 1;
    string message = 2;
}

3. Plugin Security & Sandboxing

  • Restricted Execution: Lua scripts run in an isolated state machine with disabled file system write and shell execution capabilities.
  • Plugin Signing: Production configurations require signed plugin manifests (.sig) to prevent unauthorized code execution.
  • Resource Limits: Memory usage per plugin process is capped to prevent memory leaks during scan runs.
