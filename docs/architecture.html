System Architecture Documentation

EnumScan is an event-driven, modular reconnaissance and asset intelligence platform written in Go. It is designed for authorized security assessments, continuous attack surface management, and enterprise asset inventory.

Core Component Design

1. Engine & Event Bus (internal/engine)

The core scan engine coordinates scanning execution across modules. It uses an asynchronous event bus to process discovered targets (IPs, subdomains, ports, URLs, credentials). Each event published to the bus triggers matching modules that subscribe to that event type.

2. Scope Guard (internal/scope)

Scope enforcement is mandatory. The Guard component validates targets against an authorized CIDR, IP list, or domain mask prior to dispatching any network requests. If a target is outside the configured scope, it is blocked immediately.

3. Persistence Layer (internal/store)

  • SQLite (Native Go Driver): Primary local database using modernc.org/sqlite in Write-Ahead Logging (WAL) mode with busy timeout handling to eliminate concurrent database is locked errors.
  • Postgres Store: High-concurrency enterprise backend for centralized scan repositories.
  • Neo4j Store: Knowledge graph datastore powering asset relationship graphs, trust boundaries, and lateral movement analysis.

4. Vulnerability & Risk Engine (internal/vulnerability)

Evaluates imported CVEs against active asset inventories using CVSS, EPSS (Exploit Prediction Scoring System), and CISA KEV (Known Exploited Vulnerabilities) signals. Calculates explainable composite risk scores without performing intrusive exploitation.

Concurrency & Performance Model

  • Adaptive Worker Pools: Scales concurrency workers up or down based on real-time network latency measurements.
  • Priority Queueing: Ensures high-priority critical events are evaluated ahead of background discovery tasks.
  • Thread-Safe Data Structures: Mutex-guarded maps and serialized database writes protect shared state during high-volume scans.
