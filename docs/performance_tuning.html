Performance & Concurrency Tuning Guide

Optimizing EnumScan performance ensures fast scan completion times while preventing database lock contention and host resource exhaustion.

1. Concurrency Tuning

Adjust worker pool parameters in configs/example.yaml:

engine:
  min_workers: 4
  max_workers: 16
  rate_limit_per_second: 50
  • Adaptive Scaling: EnumScan automatically monitors network RTT. If response latency exceeds 500ms, concurrency is dialed back automatically to avoid network congestion.

2. Database Tuning

SQLite WAL Mode & Connection Pool

To achieve high-throughput writes without locking issues:

PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
PRAGMA synchronous = NORMAL;

When scanning thousands of targets concurrently, ensure Go's db.SetMaxOpenConns(1) is maintained on write handles to serialize database transactions safely.

3. Distributed & Agent Scanning

For enterprise networks spanning multiple subnets, deploy remote EnumScan agents using job leasing and centralized PostgreSQL state stores to distribute execution load evenly across worker nodes.
